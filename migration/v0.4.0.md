# PLSI v0.3.4 -> v0.4.0

Moving a Grok Bot PLSI install to v0.4.0 without losing a project, a topic or its cursor: daily research becomes one
chain of runs that code drives, on two routines whatever the number of projects, in place of one routine per
project and the weekly check. The primary hub reads this file from `plsi.md` step 2 when it finds an install set up
with v0.3.4 or older; an older one applies the sections of `migration/v0.3.0.md` first (up to v0.3.4), then this
one.

The steps below run inside the normal `plsi.md` run, each at the step named; they never replace one. From the
update check, run only the `plsi.md` steps named below, in this order: no welcome and no setup cards except those
named here. Nothing changes for an install without daily research (no "PLSI research · <project>" routine and no
share set in `plsi research budget`) beyond steps 1, 6 and 7.

## What is new

- **Two routines** on the Research Orchestrator: **"PLSI research run"**, with a webhook trigger and no schedule,
  and **"PLSI research watchdog"**, every hour (`lab/research`, Daily research step 1). Code picks the project of
  each run (`plsi research run --start`); the run works it with `lab/run` and its end (`plsi research run --end`)
  asks for the next run through the webhook while the day's target is not spent. The watchdog restarts a run that
  died, asks again for a run that never started and starts the day at the user's start hour (`plsi research
  budget --start-hour`, in UTC).
- **The webhook in the secret store:** the run routine's "POST to" address and key, added once by the user as
  `PLSI_RESEARCH_HOOK_URL` and `PLSI_RESEARCH_HOOK_KEY`. Without them each watchdog check does one run in place.
- **The share is a daily target**, not a limit to stop under: research spends it each day, split across the
  projects still working, and a project that stops for the day hands its part on to the others. The weekly ceiling
  and the tenth of the week the user keeps stay hard stops.
- **Projects on hold** (`plsi research project --hold <id>` / `--resume <id>`): kept with their room, topics and
  cursors, never worked, no part of the day.
- **The run log** `research/runs.jsonl`: every run start, end, kick and check, since the bot cannot see a routine's
  history, and a `beat` for each `next` and save inside a run.
- **Runs are timed by code:** `plsi research next` stops a run with `time_box` after its 10 minutes, and a run is
  dead only after 30 minutes with no `next` or save, so a slow run is never restarted beside itself.
- **The research inbox** (`plsi research inbox [--form] [--all]`): what needs the user (ready, almost ready, needs
  you, stalled, on hold for two weeks, starving), at most one notice a day in the Research Orchestrator's own
  chat, with a question form whose answers are project commands.
- **One line per run in the project's room**, and the project's findings doc `research/projects/<project>/findings.md`,
  rebuilt by code at each run's end. The room's destination is saved in the project (`plsi research project --room`).

## What is gone

- **The routines "PLSI research · <project>"**, one per project, and the weekly **"PLSI research check"**. The
  inbox's stalled line replaces the check's line about a project with no move for two weeks; `plsi research check
  --name <note>`, the note check, stays.
- **"Off" as two actions.** Daily research off is only `plsi research budget --share 0`; no routine is disabled.
- **A run stopping early** because the topic looked thin: a run ends only when code says stop.

## What stays

- Every project, topic, cursor, note and room; the share and the ceiling (`plsi research budget`); the day's
  reservations of billed runs.
- Every other routine, bot, persona and key.

## Steps

1. **Code** (step 2, after the update): `plsi --version` says `plsi 0.4.0`.
2. **Routines** (steps 11 and 15), on the Research Orchestrator. When you are not it, ONE hub-to-hub `request`
   (skill `lab/research`, thread `setup-v0.4.0`, "Daily research moves to the research chain: migration/v0.4.0.md
   steps 2-5") and it does steps 2-5 in its own chat. Delete every "PLSI research · <project>" routine and "PLSI
   research check". Then, with daily research on (a share above 0, or any of those routines found), create "PLSI
   research run" (webhook) and "PLSI research watchdog" (hourly), ENABLED, with the text of `lab/research` Daily
   research step 1 as it reads in this release (a routine keeps the text it was saved with). Steps 3-5 run only
   when they were created.
3. **Keys** (step 6.6's secret card). ONE message, as `lab/research` Daily research step 1 words it: copy "POST to"
   and "key" from the "PLSI research run" panel and add them with the secret card as `PLSI_RESEARCH_HOOK_URL` and
   `PLSI_RESEARCH_HOOK_KEY`, never in chat. `plsi keys status` shows both set. Not added: nothing more is asked;
   the watchdog runs research in place.
4. **Rooms.** For each open project (`plsi research project`), find its room "<project title> · Project" and save
   its destination:

   ```bash
   plsi research project --room <the room's destination> --project <id>
   ```

   A project with no room gets one as `shared/sessions` says, then the same command.
5. **Start hour.** The hour the old routines ran at, or early morning the user's time, converted to UTC (code keeps
   no time zone): `plsi research budget --start-hour <0-23>`. Tell the user in one line that research now runs as a
   chain through the day, that each run posts one line in its project's room, and that only what needs them comes
   to this chat.
6. **Smoke check** (before `plsi.md` step 14), below.
7. **Version** (step 14), only once the smoke check passed: `plsi team set --version 0.4.0`.

## Known limits

- The weekly ceiling counts calendar weeks (Monday 00:00 UTC). If Grok's weekly limit resets on another day,
  research can pass the ceiling inside one Grok week, never the daily share nor the tenth of the week the user
  keeps. Counting the week from the meter itself is planned.
- One move longer than 30 minutes with no save looks like a dead run and gets restarted.

## Smoke check

```bash
git -C <repo> describe --tags          # v0.4.0
plsi --version                         # plsi 0.4.0
plsi research budget                   # share and ceiling unchanged, start_hour set
plsi research project                  # every open project as before, each with its room
plsi keys status                       # PLSI_RESEARCH_HOOK_URL and PLSI_RESEARCH_HOOK_KEY set, or the fallback
plsi research watchdog --usage <U>     # one line logged in research/runs.jsonl; may start today's run
```

No "PLSI research · <project>" or "PLSI research check" routine is left, and "PLSI research run" (webhook) and
"PLSI research watchdog" (hourly) exist ENABLED on the Research Orchestrator.
