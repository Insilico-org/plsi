# PLSI v0.4.x -> v0.5.0

Moving a Grok Bot PLSI install to v0.5.0 from v0.4.0, the last release (v0.4.1 was a dev-only interim; its
`mothership pack` changes ship here as part of v0.5.0). The primary hub reads this section from `plsi.md` step 2 when it
finds an install set up with v0.4.0 or older; an install older than v0.4.0 applies `migration/v0.4.0.md` first (the
daily-research routines), then this one.

This update is **additive and light**: it renames no routine, changes no consent or Terms, and touches no stored
data. Nothing an install already does stops or changes — an install that is not doing research or wet-lab work sees
only the new commands become available and does nothing else.

## What is new

- **Research projects and the Longevity Grok Gazette.** A research note can name a project; once a steward publishes
  it, the project is a stable, shareable Drive workspace, and the owner grows its team by their own email —
  `plsi mothership project invite` and `project revoke` draft the owner's message (sent from the address that
  submitted the note, so the Mother verifies the sender). `plsi mothership mine` shows the owner their projects and
  each one's status. When the team takes a project public, its chosen materials appear in the public **Longevity Grok
  Gazette**, browsable by MeSH tag; the working folder stays private. (Explorer `mothership`.)
- **A wet-lab journal** on the Research Orchestrator (`plsi journal`, `lab/journal`): record an experiment planned,
  run or finished — PCR, gels, RT-qPCR, westerns, flow, microscopy, cell culture, cloning, transfection, animal
  studies — a plasmid file, a bench calculation, or the journal page. It is a notebook, not a routine.
- **PLSI · Bioinformatician**, a new optional specialist (`bioinfo`): it analyses **public** omics and drug-safety
  data for a research project, one pre-registered step at a time, each with its method, numbers, a figure and a plain
  verdict (`plsi bio ...`). It touches no personal data (its `<PLSI_HOME>/analyses/` folder holds public data only).

## Fixes that need no action

- **Whole-map `--omit`**, and life events that cannot be shared for want of a shareable code are now reported in the
  package counts (`not_shared_no_code`) instead of dropped silently (`mothership pack`).
- **Map snapshots verify against the stored file**, not a re-serialised model, so a map written before a newer
  field's default no longer reads as corrupt. An install whose contribution packages were refused for a snapshot
  hash mismatch works again on update — nothing to do.
- **Install on a system-managed Python** goes straight to `~/.plsi-venv` (PEP 668 checked first), never
  `--break-system-packages` (`plsi.md` step 1).
- **Methylation clocks are offered only when they can install**: `plsi clocks check` (no build) names the missing
  package first, and `clocks install` runs it before building anything.
- **The join form**: "Not now" is no longer a kind beside the sharing choices; it is "Not now: don't join" on the
  send page. The send mode is stored with the enrollment (`mothership join --send ask|weekly`), so Data Controller
  checks a standing approval itself.
- **Handoffs are not refused for a map another bot re-projected mid-handoff**: `handoff check` returns the current
  hash (`refreshed`); only changed observations are `STALE_STATE`, fixed by a re-projection, never shown as a
  warning. Rows that touch the same states run one after another.
- **Updates**: an untracked work folder no longer blocks an update (moved to `<PLSI_HOME>/local-untracked-A.B.C/`);
  retiring old bots and other no-choice steps are approved by the one Update card; a joined user's re-consent comes
  during the update, not at the next weekly send.
- **Cards**: one open at a time; a plain chat reply answers it; a tool needing an account is offered only after
  the user says they have one.
- **Scheduled jobs and reports**: a routine that cannot run says so at once with the fix, and a report with one
  failed source still goes on the latest data.
- **Intake and answers**: fasting asked for glucose and lipids, undated items never stamped with the setup day;
  claims about files and images only from files read in the thread; searched products never presented as the
  user's; a connected wearable source is pulled, never replaced by a request for a file.

## Steps

There are no special migration steps. Inside the normal `plsi.md` run:

- **Step 2 (update):** pull and reinstall. The new `plsi journal`, `plsi bio` and `plsi mothership project/mine`
  commands become available. No routine is created or renamed, and there is no re-consent. **Tell the user in one
  line what this release adds:** an accepted research project can now be published to the public **Longevity Grok
  Gazette**, the Research Orchestrator has a **wet-lab journal**, and an optional **Bioinformatician** can analyse
  public omics and drug-safety data. A bot not doing research or wet-lab work hears only that the new commands are
  available and nothing else changes.
- **Step 7 (specialists):** the Research Orchestrator gains the lab journal. For a bot that does research (it is the
  Research Orchestrator, or has PLSI · Research Curator or PLSI · Biotech Analyst on its team) and is not already on
  the Bioinformatician's team, show ONE card **"Add PLSI · Bioinformatician? It analyses public omics and
  drug-safety data for a research project, one pre-registered step at a time — public data only."** (Add / Not
  now). Add: create it exactly as at setup. Not now: it is still offered the first time a research project needs
  public-data analysis, so nothing is lost by declining. A bot not doing research is not asked and is unaffected.

Nothing else changes; no project, topic, cursor, map or log is touched.

# PLSI v0.5.0 -> v0.5.1

Moving an install to v0.5.1 from v0.5.0, after the sections above it applies.

This update is **additive**: it renames no routine, changes no Mothership consent and touches no stored data. The
**Terms of Service and Privacy Policy change** (effective November 25, 2026: research projects, their collaborators'
addresses and the public Gazette), so the update shows the Terms card once. It needs a Longevity Mothership of v0.4.1
or newer, which reads the new `credit` of a research note.

## What is new

- **A project goes public only with its contributor's yes.** The first time the user is offered to share a note of a
  project, the same "What next?" card asks on a second page whether the public Longevity Grok Gazette may show the
  project and under what name; the note carries the answer (`credit`), and without a yes a steward cannot take the
  project public. (`lab/research` step 4, Explorer `mothership`.)
- **Fewer steps to send.** Joining the Mothership is one form (what to share, how to send it, the enrollment code)
  instead of four separate asks, and the enrollment code lasts 24 hours instead of 15 minutes. The research-note send
  card adds "Send, and don't ask for later notes"; with it, a cleared note goes without a card.
  (`orchestrator/mothership` steps 1-2, `lab/research` step 5.)
- **What 0.5.0 added is now announced**, with the Bioinformatician offered once to a bot that does research (below).
- **Installing and updating need no GitHub account**: `git clone` and `git fetch` of the public repository, run on
  the user's computer, with no editor GitHub integration (`plsi.md` step 1 and the update card).

## Steps

Inside the normal `plsi.md` run:

- **Terms (`plsi.md` step 1):** the `plsi-legal` marker of `legal/TERMS.md` is now 2026-11-25, so the Terms check
  sends its "Terms of Service" card, as after any change; nothing of this release is used until the user agrees.
- **Step 2 (update):** pull and reinstall; no new command, no routine, no re-consent. If this run did not just
  apply the v0.5.0 section (the install was already on v0.5.0), tell the user in one line what 0.5.0 and this
  release add, as that file's Step 2 says, adding that a project now goes public only with their yes.
- **Step 7 (specialists):** if this run did not just apply the v0.5.0 section, show its Bioinformatician card
  once, on the same terms (a bot that does research and is not on the Bioinformatician's team; Add / Not now).
- **An install already joined** keeps its join, kinds and send mode; nothing is asked again. A user who has not
  joined sees the new one-form join the next time it is offered.
- **A project with notes already sent:** nothing changes until the user wants it public. Its earlier notes carry no
  `credit`, so the first time they ask for it in the Gazette, send one new note of the project with their answer.

Nothing else changes; no project, topic, cursor, map or log is touched.

# PLSI v0.5.1 -> v0.5.2

Moving an install to v0.5.2 from v0.5.1, after the sections above it applies.

This update is **additive**: it renames no routine, changes no consent or Terms and touches no stored data except
the research budget's default ceiling (below).

## What is new

- **Your Chief of Staff, connected.** When the user talks to Grok through one main bot (a "Chief of Staff" or
  "Grok Bot"), PLSI finds it without asking and tells it about the install: it sends the user's PLSI requests to
  the right PLSI hub, condenses PLSI's outputs into its own digest with where to go deeper, and adds PLSI to the
  user's notes graph (Obsidian or similar) when they keep one (`plsi.md`, Instructions for Chief of Staff;
  `plsi team set --contact`).
- **Research spends less, and pauses at 85%.** The default weekly ceiling is three days' worth of the daily share
  instead of four. At 85% of the weekly usage, all research stops; the user is told which projects were running
  and picks which resume, and when the quota renews PLSI says so and offers to resume the ones on hold (`lab/run`,
  Quota).
- **Feedback after each update.** Right after an update, PLSI offers once to draft a short report of how PLSI has
  been going, for the user to send to the PLSI team by email (`orchestrator/feedback`).

## Steps

Inside the normal `plsi.md` run:

- **Step 2 (update):** pull and reinstall. Tell the user in one line what this release adds. A research budget with
  no ceiling the user named now stops at three days' worth of its share (`plsi research budget` shows it); a named
  ceiling is unchanged. Then identify the user's Chief of Staff, record it and send it its instructions
  (`plsi.md`, Instructions for Chief of Staff), with no card.
- **After the update:** the feedback card (`plsi.md` step 10, Update) is shown once.

Nothing else changes; no project, topic, cursor, map or log is touched.

# PLSI v0.5.2 -> v0.5.3

Moving an install to v0.5.3 from v0.5.2, after the sections above it applies.

This update is **fixes only**: it renames no routine and changes no Terms; the consent text changes in wording only
(0.8.1), and the only stored change is the send mode joining the Mothership enrollment (Steps). It comes from a
physician's report of a month in clinic and 23 user reports.

## What is fixed

- **No double readings from a re-exported report.** The same value of the same test at the same time is one
  reading whatever file it came from; before, a new copy of a report (a new file hash) recorded every value again.
  Readings already recorded twice stay until the user retracts them.
- **Intake checks before it records** (`processor/intake` 3c): a value that cannot be right, or one read from a
  typed summary rather than the report, is checked against the source or asked about; a date that cannot be right
  is asked about, never corrected silently; a medication, allergy or condition that contradicts the record is put
  to the user as the conflict (Stopped / Never taken / Keep), never kept side by side.
- **A request relayed by the user's own Chief of Staff or another PLSI hub** is enough to record health data, with
  who relayed it said in the result; no verbatim quote is needed.
- **Evidence memos say of a trial only what its record says today** (status, phase, dates); unpublished conference
  figures are marked or left out (`clinev/review`).
- **Heavy jobs are announced, failing browser jobs stop**: a thread likely to use a fifth or more of the week says so
  in its first line and goes on; a browser or download step that failed twice is not tried again. Documents come
  with a PDF copy, files over 20 MB are split or linked, and a file the user edited is never patched
  (`orchestrator/conduct`).
- **The Mothership catalog before anything is published** reads "not published yet" (`NOT_PUBLISHED`), not a relay
  error. The join form labels the enrollment code apart from the professional access token, and codes are never
  taken from chat. The consent text now says plainly that its never-shared list cannot be switched off: consent 0.8.1,
  wording only (what is shared is unchanged), so a joined user gets the one-tap re-accept (`CONSENT_REWORDED`) at
  the next weekly send.

## Steps

Inside the normal `plsi.md` run:

- **Step 2 (update):** pull and reinstall, and tell the user in one line: "PLSI 0.5.3: fixes to recording health
  data (no double readings, implausible values and conflicting medications are checked with you), smoother install
  and updates, fewer stuck handoffs, and clearer cards and Mothership messages." For each instance that joined the
  Mothership, store its send mode: after its consent card if it gets one (step 10, Update), else at once,
  `plsi mothership join --instance <instance> --consent-version <current marker> --send <ask|weekly>` with no
  `--kind`, the mode you remember ("Send each week without asking": `weekly`; anything else or not known: `ask`).
