# PLSI v0.1.0 -> v0.2.0

Moving an existing Grok Bot PLSI install to v0.2.0 without losing instance `me`, while adopting Display names, Research
Autopilot, the PLSI Lab and PLSI Clinic sections and the current Mothership consent. PLSI reads this file from
`plsi.md` step 2 when it finds an earlier install set up with v0.1.0; an operator can follow it by hand too.

The steps below run inside the normal `plsi.md` run, each at the step named; they never replace one. Personal,
researcher and physician installs share them; the role-specific parts are marked.

**When a newer section follows** (an install moving past this version in one go): skip this file's Install
step, because the checkout is already at the newest tag, and every step about Research Autopilot; the newest
section replaces them.

## What is new

- **Research Autopilot:** metered daily research (`autopilot/run`) inside `plsi research budget`: a share of the weekly
  meter per day (for example `--share 10`) and a weekly ceiling, by default four days' worth (40).
- **Display names** (`PLSI · …`) and avatars by tier (below).
- **PLSI Lab** (researcher): Target Hunter, Cartographer, Cohort Analyst, Grant Writer; `plsi targets` dossiers under
  `targets/<gene>/`, and the Target Hunter skills discover, evaluate, hallmarks, pandaomics and report, plus
  Cartographer field maps.
- **PLSI Clinic** (physician): Patient Coordinator, Visit Assistant, Evidence Analyst, Clinic Liaison; patient Drive
  folders (`panel/clinic`).
- **Feedback on PLSI** (usage reports) is its own opt-in, separate from joining the Mothership.
- **Mothership receipts:** after the relay delivers, `plsi mothership receipt --wait` reports stored, refused or
  pending.

## What is gone

- **Daily research by Citizen Researcher.** Autopilot owns the daily routine; Citizen Researcher stays for sessions
  the user asks for and for research notes.
- **The old default bot names** (PLSI Data Processor, Health Consultant, Nostradamus, Memory Hole, Panel, Visit Prep,
  Landscape, …). Rename in place to the Display name; never create a bot again to rename it.
- **A gene list as a shortlist.** Open Genes returns aging genes with no band and no ranking. A v0.2.0 shortlist
  comes from `targets/discover` (band, falsifier, grounded facts), and Challenger challenges it before it is shared.
- **Sending after a consent change without re-consent.** `plsi mothership pack` refuses with `CONSENT_OUTDATED` until
  the user picks the kinds again on the new text.
- **Feedback as a Mothership kind.** Feedback on PLSI needs no join and no enrollment code.

## Mothership changes

- The consent marker is now `0.7.2` (v0.1.0 installs joined on `0.7.1`). Show `mothership/consent.md` again and join
  with `--consent-version` from its HTML marker.
- On `CONSENT_OUTDATED`, show only the kinds card and keep the send mode already chosen ("Show me each file first" or
  "Send each week without asking").
- Omit `--code` on a re-join when `has_install_token` is true; the enrollment code is for the first join only.
- The kinds stay `states`, `life_events` and `scores`; Feedback on PLSI is not a kind.
- After the relay delivers, run `receipt --wait` and report stored, refused or pending. "Delivered to the relay" is
  not "stored".
- Research notes and target files go by the user's own Grok email, never inside the weekly deidentified package;
  the Mothership's answers arrive through the routine **"PLSI Mothership replies"**.
- The package still holds only codes, numbers, units and month/year dates, with sex, a 5-year age band and the
  optional ethnicity group; never age-derived values, free text or identifiers.
- Invited physicians and researchers: the professional token unlocks the catalog, releases and the findings ledger,
  independent of the personal weekly sync.

## What stays

- Instance `me` and its observations: never run `plsi init` on it again except the `--update` that `plsi.md` names.
- Every existing bot, Lab and Clinic bots included: renamed in place, never recreated. Old chats stay on the same
  agent.
- Keys, FatSecret and Google Health connections, the professional Mothership token, and the research graphs under
  `PLSI_HOME`.
- The weekly routines (check-in, talk, digest, Mothership); only the daily research routine moves to Autopilot.
- The persona: still `2.7.1`, nothing to adopt.
- The user's own health data stays out of research notes unless the user asks otherwise.
- Hub-and-spoke stays the default; expert or target-discovery group chats are optional.

## Avatars (every worker: colour `gray`)

| Tier | Shape | Examples |
|---|---|---|
| orchestrator | `star` (colour `red`) | PLSI · Chief Orchestrator |
| core | `square` | Data Manager, Health Analyst, Forecaster, Challenger, … |
| recommended, optional | `sparkle` | Device Technician, Nutritionist, Research Autopilot, … |
| researcher (Lab) | `capsule` | Target Hunter, Cartographer, Cohort Analyst, Grant Writer |
| physician (Clinic) | `heart` | Patient Coordinator, Visit Assistant, … |

Setup acknowledgements may be silent: find missing avatars by reading each bot's profile, not by chat volume.
Autopilot may acknowledge setup before it sets its gray sparkle; nudge its avatar separately.

## Steps

1. **Install** (`plsi.md` step 1). The checkout is at v0.2.0: `git -C <repo> fetch --tags`, then
   `git -C <repo> checkout v0.2.0` (a detached HEAD is fine), then reinstall into the same Python with
   `python -m pip install -e <repo>`. `plsi --version` says `plsi 0.2.0`. Keep `PLSI_HOME` pointing at the existing
   instances.
2. **Sections** (`plsi.md` steps 5 and 7). Ask for **PLSI Workers** if it is missing; then **PLSI Lab** for a
   researcher, **PLSI Clinic** for a physician, no role section for an individual. You can place a bot only when you
   create it, so ask the user to drag the existing role bots into their section.
3. **Rename and avatar every teammate** (`plsi.md` steps 3, 5 and 7). Set each bot's Display name and Description
   from `skills/shared/team`, then send it the complete first message of step 5 once, on thread `setup-v0.2.0`: its
   Opening changed, and the message sets the name and the avatar. Check that each bot's avatar colour and shape are
   set; nudge a bot whose fields stay blank.
4. **Research Autopilot** (`plsi.md` steps 6.5 and 11; researcher and personal installs with daily research on).
   Create **PLSI · Research Autopilot** (tier `optional`, gray sparkle) if missing; point the routine **"PLSI
   research"** at it (`autopilot/run`); keep or set the budget (`plsi research budget`) and the active topic
   (`plsi research topic`). Physician: skip it unless the practice also uses spare usage for research; Clinic bots do
   not replace it.
5. **Mothership re-consent** (`plsi.md` step 12). `plsi mothership status --instance me`. With `consent_current`
   false, follow the Mothership changes above.
6. **Housekeeping.** Delete leftover sample instances only through PLSI · Eraser and only on the user's explicit
   confirmation. Optional: `python -m pip install -e "<repo>[clocks]"` for methylation clocks (needs Python headers;
   blood PhenoAge works without it). Check the role with `plsi role show`.
7. **Smoke check** (before `plsi.md` step 14), below.

## Physician installs

- `plsi role show` reads `physician` before you rename the Clinic bots.
- Section **PLSI Clinic**, Display names and gray hearts from the Clinic rows of `skills/shared/team`, not Lab
  capsules.
- Never create Lab bots on a physician install, or Clinic bots on a researcher install.
- The same re-consent and the same instance `me` as researchers; patient work stays hub-and-spoke through PLSI.
- Autopilot is optional (step 4).
- Smoke check: PLSI Clinic populated, hearts set, no Lab bots, `consent_current` true.

## Smoke check

```bash
git -C <repo> describe --tags          # v0.2.0
plsi --version                         # plsi 0.2.0
plsi role show
plsi research budget
plsi research topic
plsi mothership status --instance me   # consent_current: true
plsi instances list                    # me present; sample instances gone if deleted
plsi keys status                       # the keys you expect are still true
```

Every Display name matches the roster, every avatar is set, Autopilot is idle between handoffs, the routine **"PLSI
research"** names Autopilot, and the role section holds its bots.
